# Prompt 模板迭代记录

对应 [`src/fin_risk/prompts/templates.py`](../src/fin_risk/prompts/templates.py)。四个版本都保留在代码里(而不是只留最新版本覆盖旧版本),因为这份材料真正要展示的是**迭代过程本身**——每一版只改动一个维度(角色设定 / 上下文组织 / 输出格式),这样才能看清楚每一步改动分别解决了什么问题,而不是一次性重写导致效果变化无法归因。

四个版本按 `角色设定 -> 上下文组织 -> 输出格式` 的顺序递进优化,对应任务要求的三个优化方向。每一版的 `change_notes` 也直接写在代码里(`TEMPLATE_REGISTRY`),这里做更详细的展开并附上真实生成的 prompt/报告样例(以下样例均由本仓库代码实际运行生成,公司为海螺水泥,数据截至指标计算所用的 2025 年报,非人工编造)。

## v1 基线版本

**做法**:不设角色,财务指标平铺列出数值,输出格式完全开放。

```text
system: 你是一个金融分析助手。

user:
公司: 海螺水泥(安徽海螺水泥股份有限公司)
风险评分: 27.8/100
财务指标:
- 流动比率: 数据缺失
- 资产负债率: 20.4%
- 净利润率: 9.8%
...
请分析这家公司的风险并给出评分。
```

**问题**:
- 没有角色设定,模型对"读者是谁"没有概念,专业术语解释深浅完全不受控——可能直接甩出"资产负债率""ROE"而不做任何解释。
- 上下文是数值的平铺列表,没有告诉模型哪个指标更重要、数据缺失意味着什么,模型容易把笔墨平均分配,抓不住重点。
- 输出格式开放,每次生成的报告长度、结构都不一样,没法在产品里稳定展示。

## v2:+ 角色设定

**做法**:新增角色 prompt——"资深金融风险分析师 + 服务零金融背景读者",要求先讲人话再提术语。上下文和输出格式暂不变,只隔离这一个变量看效果。

```text
system: 你是一名有15年经验的资深金融风险分析师,同时非常擅长把专业内容讲给完全没有金融背景的
普通人听懂。你的读者可能连'资产负债率'是什么都不知道,所以解释专业指标时要先讲清楚
人话含义,再提术语,不要堆砌黑话。
```

**改善**:模型解释术语的通俗程度明显提升。

**残留问题**:
- 上下文仍是平铺指标,模型经常"眉毛胡子一把抓"——对不重要的指标讲得很细,真正的风险点一笔带过。
- 完全没有外部信息,模型只能"就数字谈数字",无法回答"为什么现在风险高/这个风险是不是新出现的"这类时效性问题。

## v3:+ 上下文组织(指标分类 + 风险驱动排序 + RAG 证据注入)

**做法**:
1. 指标按"偿债能力 / 盈利能力 / 现金流质量 / 成长性"分类,每条指标带上权重、风险打分、参考基准。
2. 显式计算并单独列出"主要风险驱动指标"(按权重 × 风险分排序),引导模型优先讲这些。
3. 注入 RAG 检索到的企业公告/新闻作为证据,并标好 `[证据n]` 编号。

```text
主要风险驱动指标(按贡献度排序):
- 营收环比/同比增长率: -9.3% — 规范定义: ...
- 净资产收益率(ROE): 4.2% — 规范定义: ...
- 净利润率: 9.8% — 规范定义: ...

检索到的相关企业公告/新闻:
[证据1] 2026-03-26 | announcement | 海螺水泥2025年年度报告
    公司发布2025年年度报告:营业收入825.32亿元,同比下降9.33%,为近年来持续第二年下滑;...
[证据2] 2025-10-30 | announcement | 海螺水泥2025年第三季度报告
    ...营收下滑但利润逆势增长,主要受益于原燃材料及生产成本管控。
```

**改善**:分析重点明显更聚焦在真正的风险驱动指标上;分析开始具备**时效性**——能引用最近的评级/减值/股东增持等真实事件,而不仅仅是静态财务数字。这一步直接对应任务里"结合企业公告、新闻资讯构建 RAG 检索增强流程"的要求。

**残留问题**:输出格式仍是自由发挥("请给出通俗解读和主要风险点"这种开放式指令),证据引用不规范——模型有时引用编号,有时不引用,报告长度和结构在多次生成之间不稳定,难以稳定解析或做前端展示。

## v4:+ 输出格式约束 + 准确性护栏(当前生产版本)

**做法**:在 v3 的角色 + 上下文基础上,新增两类约束:

1. **锁定五段式输出结构**:一句话结论 / 风险评分与等级 / 关键指标通俗解读 / 主要风险点与证据 / 需关注的趋势与免责声明。用 `<公司概况>` `<分类别指标详情>` 等类 XML 标签分隔上下文,减少模型混淆"这是数据"还是"这是要输出的格式说明"。
2. **准确性护栏**(直接针对"提高模型对风险指标解释的准确性"这个要求):
   - 要求指标解释必须"以提供的规范定义为准转述",不允许模型用自己的知识编造定义或行业基准——避免模型凭训练知识"背"一个不准确或过时的行业基准。
   - 要求每条风险论断必须有 `[证据n]` 引用或明确标注"基于历史财务数据推断",不允许编造未提供的事件/数据。
   - 明确不得给出买入/卖出等投资建议,只做风险状况的解释,控制合规风险。

```text
system: 你是一名服务于普通投资者的资深金融风险分析师,拥有15年信用风险与财务分析经验。...
写作要求:
1. 先讲人话,再提术语;需要用生活化类比解释专业概念,但类比之后必须回到准确的数据结论。
2. 语气客观克制,不夸大风险也不淡化风险,不使用'暴雷''雷区'等煽动性词汇。
3. 解释每个指标含义时,必须以用户提供的'规范定义'为准转述,不能凭自己的知识编造定义、
行业基准或未经验证的事实。
4. 每一条风险论断都必须有证据支撑:要么引用提供的[证据n],要么明确标注'基于历史财务数据推断'。
严禁编造未被提供的公告、新闻或数据。
5. 不得给出买入/卖出/持有等投资建议,只做风险状况的解释与信息整理。
```

**v4 生成的最终报告示例**(MockLLMClient 离线生成,海螺水泥,数据截至 2025 年报,2026-07-05 生成):

```text
【一句话结论】
海螺水泥(安徽海螺水泥股份有限公司)当前风险等级为「中等风险」(评分27.8/100),主要受营收环比/同比增长率影响。

【风险评分与等级】
综合风险评分 27.8/100,对应风险等级为「中等风险」(评分越高代表风险越高)。本次评估中,有55%的指标权重基于可获得的公开数据计算,其余部分因数据未披露暂缺。

【关键指标通俗解读】
- 营收环比/同比增长率(-9.3%): 公司这一期收入相比上一期是在增长还是萎缩,反映业务景气度和市场需求的变化趋势。目前参考基准为「连续下滑通常是经营恶化的早期信号,需要结合行业整体环境判断。」。
- 净资产收益率(ROE)(4.2%): 股东投入公司的每一块钱本金,这个报告期能带来多少回报,可以理解成'股东这笔投资的收益率'。目前参考基准为「长期能维持在10%以上一般被认为是较优秀的盈利水平,持续为负需要重点关注。」。
...

【主要风险点与证据】
- 营收环比/同比增长率处于偏高风险水平(-9.3%)。[证据1] 2026-03-26 「海螺水泥2025年年度报告」与该指标反映的风险方向一致。
- 净利润率处于偏高风险水平(9.8%)。以下判断基于历史财务数据推断,暂无检索到与之明确对应的外部公开信息佐证。

【需关注的趋势与免责声明】
建议持续关注上述风险指标后续的季度变化趋势,以及是否有新的公开公告或新闻进一步影响评估结论。
本报告基于截至2026-07-05的公开数据由系统自动生成,仅作为分析参考,不构成投资建议。
```

注意最后一条风险点(净利润率)明确写了"暂无检索到与之明确对应的外部公开信息佐证",而不是硬凑一条不相关的证据——这正是 v4 护栏(第4条写作要求)想要的效果。

## 已知局限 / 后续可以继续优化的方向

- **MockLLMClient 的证据匹配是规则匹配,不是语义理解**:它只是在检索结果里找带"风险类"标签(如"评级下调""营收下滑")的文档去匹配风险点,不保证语义上真的贴题(见上面 ROE 那条引用第三季度报告的例子,标签匹配但内容关联并不紧密)。真正调用 Claude API 时,模型会阅读证据全文做语义判断,应该比这更准确——这也是为什么系统把"规则应该怎么约束模型"写进了 v4 的 system prompt,而不是指望模型自己隐式做对。
- **行业基准是统一阈值,没有分行业校准**:比如海螺水泥(水泥制造)和美的集团(家电)用的是同一套资产负债率评分曲线,现实中不同行业的健康杠杆水平不同,更严谨的版本应该按行业设置不同基准点。
- **v1-v3 目前只做了 prompt 设计和结构对比,还没有做量化评估**(比如同一批公司分别用 4 个版本跑一遍真实 Claude API,人工或用另一个模型打分对比准确性/可读性/证据引用率)。这是"持续优化"下一步的自然延伸,目前受限于真实 API 调用成本还未执行,`examples/run_demo.py --llm anthropic --prompt-version vN` 已经可以直接跑起来做这个实验。
